Bludia authenticates **your app's users** (end users) against a collection in your own project. There's no separate user database: a user is a record in a collection like `users`, `customers`, or `staff`.

```text
users collection                 Authentication guard "users"
├── email      (login field)  ◄── login field: email
├── password   (auto-added)   ◄── password field (hashed)
├── full_name
└── phone
```

## The flow

```text
1. Register    POST /auth/users/register   { email, password, full_name }   → session
2. Log in      POST /auth/users/login      { login, password }              → session
3. Use the API GET  /collections/orders/records   Authorization: Bearer <access_token>
4. Refresh     POST /auth/users/refresh    { refresh_token }                → new session
5. Log out     POST /auth/users/logout     { refresh_token }
```

A **session** looks like this:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "q3Jx...(80 characters)",
  "token_type": "Bearer",
  "expires_in": 900,
  "record_id": 42
}
```

## Set up authentication

<Steps>
  <Step title="Create a users collection">
    Add a collection (for example `users`) with a login field such as `email`, plus any profile fields.
  </Step>
  <Step title="Create a guard">
    Go to **Authentication** → **Guards** → **Create guard**. Pick the collection and the login field. Bludia adds a `password` field and a default role, `user`. See [Guards](/authentication/guards).
  </Step>
  <Step title="Grant permissions">
    Give the `user` role access to the collections your app needs. See [Roles & permissions](/authorization/roles-and-permissions).
  </Step>
  <Step title="Create an end_users API key">
    In **API** → **API Keys**, create a key with auth type `end_users` and add your app's origin. See [API keys](/api/api-keys).
  </Step>
  <Step title="Build login and sign-up screens">
    Call the auth endpoints from your app. See [Register & login](/authentication/register-and-login).
  </Step>
</Steps>

## Security built in

| Protection | How |
| :-- | :-- |
| Password storage | Hashed with bcrypt; never returned by the API |
| Minimum password length | 8 characters (add more rules on the password field) |
| Brute-force protection | Auth endpoints allow 10 requests per minute per IP and route |
| Login auditing | Every login attempt is logged with IP, user agent, and result |
| Refresh token rotation | Each refresh revokes the old refresh token |
| Account status | Users with status `inactive`, `banned`, or `suspended` can't log in |
| Password reset | Revokes all of the user's sessions |
| Tenant isolation | Tokens only work for the project and guard that issued them |
