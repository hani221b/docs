## How hooks run

```text
Your Go code ──TinyGo──► WebAssembly module
                              │
                              ▼
                 Bludia hook runtime (sandbox)
                 ├── own memory, CPU fuel, and time budget
                 ├── no direct network, file system, or OS access
                 └── host functions ↔ Bludia: record context, queries,
                                      writes, messages, logs
```

Each execution is isolated: hooks can't see other projects' data, other executions' memory, or the server they run on. All data access goes through the SDK and is scoped to your project.

## Limits

| Resource | Default | Maximum | Manifest key |
| :-- | :-- | :-- | :-- |
| Execution time | 10,000 ms | 30,000 ms | `timeout_ms` |
| Memory | 32 MB | 128 MB | `memory_limit_bytes` |
| CPU fuel (instruction budget) | 10,000,000 | 100,000,000 | `fuel_limit` |
| Rows per query | 50 | 200 | `Limit(n)` in code |
| Hooks per collection per event | 1 | 1 | |

Values above the maximum are lowered to the maximum.

```json Manifest example
{
  "timeout_ms": 20000,
  "memory_limit_bytes": 67108864,
  "fuel_limit": 50000000
}
```

## What happens at a limit

| Limit hit | Result |
| :-- | :-- |
| Timeout | Execution stops with "Hook timed out after N ms" |
| Fuel or memory exhausted | Execution stops with an error |
| In a **before** hook | The write is rejected |
| In an **after** hook | Logged as an error; the write already happened |

## What hooks can't do

- Make HTTP requests to outside services directly.
- Read or write files.
- Keep state between executions (use a collection instead).
- Run longer than 30 seconds.

<Note>Need to call an external API? Write a record to a collection like `outbox` from your hook and have your own server process it.</Note>
