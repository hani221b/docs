</Info>

**Bludia is the backend for your application.** You model your data in the dashboard, and Bludia gives you a secure REST API, user authentication, permissions, and server-side logic. You keep building your frontend with the tools you already use.

```text
Your frontend (React, Next.js, Vue, Flutter, mobile, any HTTP client)
                │  HTTPS + X-BLUDIA-API-KEY (+ Bearer token for signed-in users)
                ▼
            Bludia REST API  ──►  Collections & records (PostgreSQL)
                │
                ├── Authentication guards (register, login, JWT sessions)
                ├── Roles, permissions, and row-level security
                ├── Hooks (Go → WebAssembly, before/after each write)
                ├── Messaging (email templates)
                └── Files, reports, dashboards, scheduled tasks
```

## How you build with Bludia

<Steps>
  <Step title="Create a project">
    A [project](/projects) is one backend: its own data, users, keys, and settings.
  </Step>
  <Step title="Model your data">
    Add [collections](/database/collections) (like tables) and [fields](/database/fields) (like columns). Connect them with [relations](/database/relations).
  </Step>
  <Step title="Create an API key">
    Generate an [API key](/api/api-keys) and send it in the `X-BLUDIA-API-KEY` header.
  </Step>
  <Step title="Add users and permissions">
    Create an [authentication guard](/authentication/guards), then grant [roles](/authorization/roles-and-permissions) access to collections.
  </Step>
  <Step title="Add business logic">
    Write [hooks](/hooks/overview) for validation, side effects, and notifications.
  </Step>
  <Step title="Connect your frontend">
    Call the API from [your frontend or server](/frontend/overview).
  </Step>
</Steps>

## What you can build

Bludia fits apps whose core is structured business data and users with different access levels:

<Columns cols={2}>
  <div>
    - CRMs and sales pipelines
    - Admin panels and internal tools
    - Customer and partner portals
    - Booking and scheduling systems
  </div>
  <div>
    - SaaS application backends
    - Mobile app backends
    - Directories and marketplaces
    - Reporting and operations systems
  </div>
</Columns>

For example, a booking app might use:

| Bludia feature | Used for |
| :-- | :-- |
| Collections | `customers`, `services`, `staff`, `bookings` |
| Authentication guard | Customer sign-up and login |
| Roles and row-level security | Customers see only their own bookings; staff see all |
| Hooks | Reject double bookings, send confirmation emails |
| Reports | Revenue and bookings per service |

## Bludia is not your frontend

Bludia does not render your user interface. You build the UI with any framework, and it talks to Bludia over HTTPS. You can connect several frontends (web, mobile, admin) to the same project.
