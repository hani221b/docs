A **project** is one complete backend. Everything you build in Bludia lives inside a project, and nothing is shared between projects.

## What a project contains

<CardGroup cols={3}>
  <Card title="Data" icon="database" color="#3B82F6">

  </Card>
  <Card title="Access" icon="key" color="#8B5CF6">
    API keys, authentication guards, roles, row policies.
  </Card>
  <Card title="Logic" icon="webhook" color="#F59E0B">
    Hooks, messaging channels and templates, functions.
  </Card>
  <Card title="Content" icon="folder-open" color="#6366F1">
    Files, PDF templates.
  </Card>
  <Card title="Insights" icon="chart-column" color="#14B8A6">
    Reports and dashboards.
  </Card>
  <Card title="Team" icon="users" color="#64748B">
    Team members and their project roles.
  </Card>
</CardGroup>

```text
Task Manager (project)
├── Collections:   tasks, users, categories
├── Relations:     tasks → users, tasks → categories
├── API keys:      "Web app" (end_users), "Nightly sync" (platform)
├── Guards:        users (login field: email)
├── Roles:         user, admin
├── Hooks:         tasks.beforeInsert, tasks.afterUpdate
├── Messaging:     SMTP channel, "Task assigned" template
└── Settings, team members
```

## Create a project

<Tabs>
  <Tab title="From scratch" icon="plus">
    <Steps>
      <Step title="Open the dashboard">Sign in at [bludia.com](https://bludia.com).</Step>
      <Step title="Select Create Project">Give the project a name, such as `Booking System`.</Step>
      <Step title="Open the project">Start adding collections and fields.</Step>
    </Steps>
  </Tab>
  <Tab title="From a template" icon="layout-template">
    Pick a ready-made template (for example a CRM or school management system). Bludia creates its collections, fields, and relations for you. Edit anything afterwards.
  </Tab>
  <Tab title="With AI" icon="sparkles">
    Describe your app in plain language, for example *"A gym membership system with members, plans, payments, and class bookings."* Bludia proposes a schema (collections, fields, relations). Review it, then confirm to create the project.

    You can also use AI later to propose schema changes to an existing project and apply them after review.
  </Tab>
</Tabs>

<Tip>
  You can try Bludia before signing up. A guest gets a temporary project; when you create an account or log in, that project is claimed by your account. Some features (API keys, guards, hooks, messaging, uploads, invitations) require an account.
</Tip>

## One project or several?

Use **one project per independent application**.

| Situation | Recommendation |
| :-- | :-- |
| Web app and mobile app share the same users and data | **One project**, two API keys |
| Customer portal and internal admin over the same data | **One project**, separate roles |
| Two unrelated client apps | **Two projects** |
| Development vs production data | Separate projects, or key `environment` labels for traffic separation |

If parts of your system share users, permissions, and data, they belong in the same project.

## Project settings and team

From the project settings you can rename or delete the project and invite team members. Team members get **project roles** that control what they can do in the dashboard, such as viewing or creating API keys. See [Team members](/authorization/team-members).

<Warning>Deleting a project deletes its data, keys, and configuration. Export your data first; see [Backups & exports](/hosting/backups-and-exports).</Warning>
