# Build your first backend with Bludia

Bludia provides the backend infrastructure your application needs without requiring you to build and maintain it yourself.

Create a project, define your data model, configure API access, and connect your frontend. Bludia handles the underlying database, API infrastructure, and backend operations.

In this guide, you'll build a simple Tasks API and learn the fundamentals of working with Bludia.

By the end, you'll have a functional backend that can be connected to any web or mobile application.

<Card title="What you'll build" icon="check-circle">
  A simple **Tasks API** with the following structure:

  ```text
  Bludia Project
  │
  └── tasks
      ├── title
      ├── description
      ├── completed
      └── status
  ```

  You'll create records, access them through the API, and connect your application to Bludia.
</Card>

## Before you start

You'll need:

- A Bludia account
- Access to the Bludia dashboard
- An application or HTTP client capable of making API requests

You don't need to install a backend framework, configure a database server, or build CRUD endpoints.

## Create your backend

<Steps>
  <Step title="Create a project">
    Sign in to your Bludia dashboard and create a new project.

    Give your project a name, such as **Task Manager**.

    A project is the foundation of your backend. It contains your collections, relationships, API configuration, authentication, permissions, and other backend resources.

    Once created, open your project from the dashboard.

    <Tip>
      Create one Bludia project for each independent application or backend you want to manage.
    </Tip>
  </Step>
  <Step title="Create your first collection">
    Navigate to **Collections** → **Create Collection**.

    Create a collection called `tasks`.

    A collection represents a type of data in your application. For example, a CRM might have collections for customers, contacts, companies, and deals.

    For this quickstart, we'll use a single `tasks` collection.
  </Step>
  <Step title="Define your data model">
    Open your `tasks` collection and add the following fields:

    | Field | Type |
    | :-- | :-- |
    | `title` | Text |
    | `description` | Text |
    | `completed` | Boolean |
    | `status` | Text |

    Your collection should now look something like this:

    ```text
    tasks
    │
    ├── id
    ├── title
    ├── description
    ├── completed
    ├── status
    ├── created_at
    └── updated_at
    ```

    Bludia manages the underlying data infrastructure and API operations for your collection. You don't need to manually create database tables or implement CRUD endpoints.
  </Step>
  <Step title="Create your first record">
    Open the **Records** section of your collection and create a new task:

    ```json
    {
      "title": "Learn Bludia",
      "description": "Build my first Bludia backend",
      "completed": false,
      "status": "todo"
    }
    ```

    Save the record.

    Your first piece of application data is now stored in Bludia.
  </Step>
  <Step title="Generate API access">
    To access your project from an external application, create an API key.

    Navigate to **Project** → **API** → **API Keys**.

    Create a new key and give it an appropriate name, such as **Task Manager Frontend**.

    Copy the generated key and store it securely.

    <Warning>
      Treat API keys as credentials. Never commit private keys to Git or expose sensitive server-side credentials in publicly accessible frontend code.
    </Warning>

    Learn more in [API Keys](/api/api-keys).
  </Step>
  <Step title="Make your first API request">
    Your Bludia project exposes API endpoints that allow external applications to interact with your collections.

    Use the following example to retrieve your task records:

    ```bash
    curl -X GET "YOUR_API_ENDPOINT" \
      -H "Accept: application/json" \
      -H "X-BLUDIA-API-KEY: YOUR_API_KEY"
    ```

    Replace the endpoint and credentials with the values provided by your project.

    A successful request returns your collection data as JSON.

    The complete endpoint structure and available parameters are documented in the [API Reference](/api-reference/overview).
  </Step>
  <Step title="Create records through the API">
    You can also create records programmatically without opening the dashboard.

    ```bash
    curl -X POST "YOUR_API_ENDPOINT" \
      -H "Accept: application/json" \
      -H "Content-Type: application/json" \
      -H "X-BLUDIA-API-KEY: YOUR_API_KEY" \
      -d '{
        "title": "Build a dashboard",
        "description": "Connect a frontend to Bludia",
        "completed": false,
        "status": "todo"
      }'
    ```

    Bludia creates the record in your `tasks` collection.

    You can also retrieve, update, search, filter, and delete records through the API, depending on your project's configuration and permissions.

    See [Records API](/api/records) for more information.
  </Step>
  <Step title="Connect your frontend">
    Bludia works with the frontend technology you already use.

    For example, a React application can communicate with Bludia using the standard Fetch API:

    ```javascript
    const response = await fetch(
      "YOUR_API_ENDPOINT",
      {
        headers: {
          "Accept": "application/json",
          "X-BLUDIA-API-KEY": process.env.BLUDIA_API_KEY
        }
      }
    );
    
    const data = await response.json();
    ```

    You can connect Bludia to:

    - React
    - Next.js
    - Vue
    - Flutter
    - JavaScript and TypeScript applications
    - Native mobile applications
    - Other backend services

    See [Frontend Integration](/frontend/overview) for more examples.

    <Warning>
      The example above assumes a trusted server-side environment. Never expose a private API key in browser-delivered JavaScript. For public-facing applications, use an appropriate authentication and authorization configuration.
    </Warning>
  </Step>
</Steps>

## Go beyond basic data operations

You've now created a working backend and connected it to an external application.

But Bludia provides more than collections and API endpoints. As your application grows, you can introduce additional backend capabilities without building everything from scratch.

<Steps>
  <Step title="Add authentication">
    For applications with multiple users, you'll typically want to introduce authentication.

    Bludia authentication allows your application to identify users and establish authenticated sessions.

    ```text
    User
     │
     ▼
    Your Frontend
     │
     │ Login
     ▼
    Bludia Authentication
     │
     ▼
    Authenticated User
     │
     ▼
    Bludia API
    ```

    Start with [Authentication](/authentication/overview).
  </Step>
  <Step title="Configure authorization">
    Once users can authenticate, you can control what they are allowed to access and modify.

    For example:

    ```text
    Administrator
        │
        ├── Create tasks
        ├── Update tasks
        ├── Delete tasks
        └── View tasks
    
    Employee
        │
        ├── Create tasks
        ├── Update tasks
        └── View tasks
    ```

    Bludia provides roles and permissions to implement this type of access control.

    Learn more in [Authorization & Security](/security/overview).
  </Step>
  <Step title="Add custom backend logic">
    Not every application requirement can be handled through basic data operations.

    You might need to:

    - Automatically update fields
    - Validate incoming data
    - Send emails or notifications
    - Call external APIs
    - Perform custom calculations
    - Execute application-specific business logic

    This is where **Hooks** come in.

    ```text
    Task Created
         │
         ▼
    After Create Hook
         │
         ├── Validate task
         ├── Update related data
         └── Send notification
    ```

    Learn more about [Hooks](/hooks/overview).
  </Step>
  <Step title="Build a real application">
    The same Bludia building blocks can be combined to create different types of applications.

    **CRM**

    ```text
    customers
    contacts
    companies
    deals
    activities
    users
    ```

    **Booking system**

    ```text
    customers
    services
    staff
    bookings
    availability
    payments
    ```

    **Internal management system**

    ```text
    employees
    departments
    tasks
    requests
    documents
    reports
    ```

    Start with the data your application needs and introduce additional capabilities as your requirements evolve.
  </Step>
</Steps>

## The Bludia workflow

A typical Bludia development workflow looks like this:

```text
Create Project
     │
     ▼
Model Your Data
     │
     ▼
Create Collections
     │
     ▼
Add Fields & Relations
     │
     ▼
Configure API Access
     │
     ▼
Add Authentication
     │
     ▼
Configure Authorization
     │
     ▼
Add Backend Logic
     │
     ▼
Connect Your Frontend
     │
     ▼
Integrations & Reports
     │
     ▼
Production Application
```

You can introduce these capabilities incrementally. You don't need to configure everything before making your first API request.

Bludia gives you the backend foundation so you can focus on building the actual product.
