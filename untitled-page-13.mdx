# Users

Users are the people who can access your application through Bludia's authentication system.

Bludia provides built-in user management so you don't have to build and maintain your own authentication database, password handling, or account infrastructure.

Every authenticated user has an identity that your application can use to personalize experiences, associate records, and enforce access policies.

<Info>
  Bludia manages authenticated users separately from regular application collections. This keeps account management independent from your application's business data.
</Info>

## Understanding user accounts

A user account contains authentication-related information and account metadata.

Typical user information includes:

- Unique user identifier
- Email address
- Password credentials
- Account status
- Email verification status
- Account timestamps
- Additional configured user attributes

<Warning>
  Password credentials are managed by Bludia's authentication infrastructure. Never store passwords as ordinary collection fields or expose sensitive authentication information through your frontend.
</Warning>

## Users vs. Collections

Bludia separates authentication identities from application data.

For example, consider a booking application:

## User registration

Users can create accounts through your application's registration flow when registration is enabled.

Bludia handles the account creation process and associated authentication operations.

<Steps>
  <Step title="User submits registration">
    Your frontend collects the required registration information.
  </Step>
  <Step title="Bludia processes the request">
    Bludia validates the supplied information and creates the account.
  </Step>
  <Step title="User authenticates">
    The user can authenticate through your configured login flow.
  </Step>
  <Step title="Application access">
    Authenticated requests are evaluated against your project's authentication and authorization configuration.
  </Step>
</Steps>

## User authentication

Once an account exists, users can authenticate through your application's login flow.

Bludia verifies the supplied credentials and establishes authentication according to your project's configuration.

After authentication, requests to protected endpoints are evaluated against the configured access policies.

## User permissions

Authentication identifies a user. Authorization determines what that user can do.

Bludia allows you to organize users into roles and assign permissions to control access to your application's functionality.

## Security best practices

Protecting user accounts is essential for every production application.

<AccordionGroup>
  <Accordion title="Protect authentication credentials" icon="lock">
    Never expose passwords, private tokens, or sensitive authentication information through frontend code or public API responses.
  </Accordion>

  <Accordion title="Apply least-privilege access" icon="shield">
    Give users only the permissions required to perform their tasks.
  </Accordion>

  <Accordion title="Protect user-owned records" icon="database">
    Apply row-level authorization to prevent users from accessing records belonging to other users.
  </Accordion>

  <Accordion title="Restrict administrative operations" icon="user-lock">
    Ensure that sensitive account management operations are available only to authorized administrators.
  </Accordion>

  <Accordion title="Review public endpoints" icon="globe">
    Make sure public endpoints expose only information intended to be publicly accessible.
  </Accordion>
</AccordionGroup>
