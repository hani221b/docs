# Login & Registration

Bludia provides built-in authentication capabilities that allow users to create accounts and securely access your applications.

Instead of implementing password handling, credential validation, and authentication infrastructure yourself, you can use Bludia to manage the authentication process while integrating it with your frontend.

Whether you're building a customer portal, SaaS platform, booking system, or internal application, you can configure authentication to match your requirements.

<Info>
  Authentication is managed by Bludia. Your frontend is responsible for collecting user credentials and communicating with the Bludia API.
</Info>

## How registration works

Registration allows new users to create accounts in your application.

A typical registration flow looks like this:

<Steps>
  <Step title="Collect user information">
    Your frontend displays a registration form and collects the required information, such as email address and password.
  </Step>
  <Step title="Submit registration request">
    Your frontend sends the registration information to the Bludia authentication API.
  </Step>
  <Step title="Validate and create account">
    Bludia processes the registration request, validates the supplied information, and creates the user account.
  </Step>
  <Step title="Complete registration">
    The user can proceed according to your configured authentication and email verification requirements.
  </Step>
</Steps>

## How login works

Once a user has an account, they can authenticate using your application's login form.

<Steps>
  <Step title="Collect credentials">
    Your frontend asks the user for their configured login credentials.
  </Step>
  <Step title="Submit login request">
    The credentials are sent to the Bludia authentication API over HTTPS.
  </Step>
  <Step title="Verify credentials">
    Bludia validates the supplied credentials against the user account.
  </Step>
  <Step title="Establish authentication">
    When authentication succeeds, Bludia returns the configured authentication result.
  </Step>
  <Step title="Access protected resources">
    Your frontend uses the authentication result when communicating with protected API endpoints.
  </Step>
</Steps>

<Info>
  The authentication response and subsequent request requirements depend on your project's configured authentication method. Refer to the API Authentication documentation for the exact integration details.
</Info>

## Custom login fields

Not every application identifies users using an email address.

Depending on your requirements, you may want users to authenticate using another identifier.

Examples include:

- Username
- Employee ID
- Membership number
- Phone number
- Custom account identifier

Bludia supports configurable login fields so you can adapt authentication to your application's user management requirements.

## Email verification

You may want to verify user email addresses before allowing access to certain application features.

Email verification helps ensure that users have access to the email address associated with their accounts.

A typical verification flow involves:

1. A user registers an account.
2. Bludia initiates the configured email verification process.
3. The user receives a verification message.
4. The user completes the verification process.
5. The account's verification status is updated.

You can use verification requirements as part of your application's authentication and authorization rules.

## Password security

Bludia manages password credentials as part of its authentication infrastructure.

When implementing login and registration forms, follow these recommendations:

- Always transmit credentials over HTTPS.
- Never store passwords in frontend storage.
- Never log passwords or authentication credentials.
- Avoid exposing sensitive user information in API responses.
- Use the built-in password recovery functionality instead of implementing your own password reset mechanism.
