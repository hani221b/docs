Not every user in your application should have access to the same functionality or data.

An administrator may need full access to manage an application, while a manager may only need to access operational data. Regular users should only have access to the resources they are authorized to use.

Bludia provides role-based access control (RBAC), allowing you to organize users into roles and define what each role can access and perform.

Instead of implementing access checks throughout your frontend and backend, you can configure access policies centrally in your Bludia project.

<Info>
  Roles organize users into groups. Permissions define what those groups are allowed to do. Bludia evaluates access policies on the backend, so frontend restrictions alone are never sufficient for protecting application data.
</Info>

## Understanding roles and permissions

Roles and permissions work together to determine what authenticated users can do.

## How role-based access control works

The authorization process typically follows these steps:

<Steps>
  <Step title="Create roles">
    Define the different user categories required by your application.
  </Step>
  <Step title="Define permissions">
    Determine which operations each role is allowed to perform.
  </Step>
  <Step title="Assign roles to users">
    Associate users with the appropriate roles.
  </Step>
  <Step title="Evaluate requests">
    When a user makes an API request, Bludia evaluates the configured access policies.
  </Step>
  <Step title="Allow or reject access">
    The operation is permitted only when the applicable authorization requirements are satisfied.
  </Step>
</Steps>

## Collection permissions

Your application collections contain business data, and different user roles may require different levels of access to each collection.

For example, a CRM application might have the following collections:

| Collection | Administrator | Manager | Employee |
| --- | --- | --- | --- |
| Leads | Full access | Read / Write | Read / Write |
| Customers | Full access | Read / Write | Read |
| Employees | Full access | Read | Restricted |
| Settings | Full access | Restricted | Restricted |

This allows you to define access policies based on the responsibilities of each user group.

## Configuring roles and permissions

When setting up access control for a new project, we recommend the following workflow:

<Steps>
  <Step title="Identify user categories">
    List the different types of users who will interact with your application.

    For example: administrators, managers, employees, and customers.
  </Step>
  <Step title="Create roles">
    Create a role for each user category that requires a distinct access policy.
  </Step>
  <Step title="Define collection access">
    Determine which collections each role should be able to access.
  </Step>
  <Step title="Configure operations">
    Define whether each role can read, create, update, or delete records.
  </Step>
  <Step title="Assign roles">
    Associate each user with the appropriate role.
  </Step>
  <Step title="Test authorization">
    Test the application using accounts with different roles to verify that access restrictions work as expected.
  </Step>
</Steps>
